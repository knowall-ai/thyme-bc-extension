= Solution Design
:toc:

== Overview

The Thyme BC Extension provides custom API endpoints that expose Business Central Job, Job Task, Time Sheet, Resource, and Time Entry data with additional fields not available in the standard BC API v2.0.

== Problem Statement

The standard BC API v2.0 `/projects` endpoint only returns 4 fields:

* `id` - System GUID
* `number` - Job number
* `displayName` - Combined customer/project name
* `lastModifiedDateTime` - Last modified timestamp

This is insufficient for the Thyme time tracking app which needs:

* Customer name and number (for grouping projects by client)
* Person responsible (project manager)
* Project status (to filter active projects)
* Start/end dates (for project timeline)
* Job tasks (for time entry allocation)
* Time sheets with approval status (Open, Submitted, Approved, Rejected)
* Resources with capacity/hours targets
* Posted time entries from Job Ledger

== Time Entry Lifecycle

Understanding the distinction between Time Sheets and Time Entries is crucial for integrating with Business Central.

=== Lifecycle Diagram

[source]
----
User enters time    → timeSheetLine (Status: Open)
        ↓
User submits        → timeSheetLine (Status: Submitted)
        ↓
Manager approves    → timeSheetLine (Status: Approved)
        ↓
Posted to ledger    → timeEntry (Job Ledger Entry - permanent record)
----

=== Time Sheet Lines vs Time Entries

[cols="1,2,2", options="header"]
|===
| Aspect | `timeSheetLines` | `timeEntries`

| BC Table
| Time Sheet Line (table 951)
| Job Ledger Entry (table 169)

| Stage
| In approval workflow
| Posted to ledger (finalized)

| Status
| Open → Submitted → Approved
| N/A (already posted)

| Editable
| Yes (until posted)
| No (permanent accounting record)

| Purpose
| Track & approve time before posting
| Accounting, billing, historical reports
|===

=== When to Use Each Endpoint

* **`/timeSheets` and `/timeSheetLines`**: Use for approval workflows, viewing pending/submitted time entries, and editing unposted entries. These represent time that is still in the review process.

* **`/timeEntries`**: Use for finalized reports, billing calculations, and historical records. These are permanent ledger entries that cannot be modified.

==== Creating a Time Sheet

`POST /timeSheets` with `resourceNo` and `startingDate` creates a time sheet header
equivalent to the one BC's *Create Time Sheets* batch job produces. The extension
supplies the rest on insert:

* `number` from the **Time Sheet Nos.** series on Resources Setup
* `endingDate` as `startingDate + 6` days
* `ownerUserId` and `approverUserId` from the resource card

The insert is rejected if the resource does not have **Use Time Sheet** enabled, if no
time sheet number series is configured, or if the period overlaps an existing time
sheet for that resource.

=== Timesheet Reviews API (Page 50109)

Maps to the extension's own `Thyme Timesheet Review` table (table 50100). Written by an AI
agent (insert/modify/delete) and read by Thyme.

[cols="1,1,1", options="header"]
|===
| API Field | Table Field | Notes

| id | SystemId | Primary key (GUID), read-only
| entryNo | Entry No. | AutoIncrement primary key, read-only
| timeSheetNo | Time Sheet No. | Required; relates to Time Sheet Header
| versionStamp | Version Stamp | Required; latest lastModifiedDateTime across the time sheet's lines and details when reviewed
| verdict | Verdict | Enum `Thyme Review Verdict`: Approve, Check, Query (defaults to Check)
| summary | Summary | Text[2048]
| reviewer | Reviewer | Text[100]
| reviewedAt | Reviewed At | Defaults to the current date/time on insert
| lastModifiedDateTime | SystemModifiedAt | For sync
|===

A secondary key on (Time Sheet No., Reviewed At) serves the "latest review" query
`$filter=timeSheetNo eq 'TS00001'&$orderby=reviewedAt desc&$top=1`. Deleting a review
deletes its review lines.

=== Time Suggestions API (Page 50111)

Maps to the `Thyme Time Suggestion` table (table 50102). Written by an AI agent; read,
accepted and dismissed by Thyme.

[cols="1,1,1", options="header"]
|===
| API Field | Table Field | Notes

| id | SystemId | Primary key (GUID), read-only
| entryNo | Entry No. | AutoIncrement primary key, read-only
| resourceNo | Resource No. | Required; relates to Resource
| date | Date | Required
| quantity | Quantity | Hours
| jobNo | Job No. | Relates to Job
| jobTaskNo | Job Task No. | Relates to Job Task within Job No.
| description | Description | Text[250]
| source | Source | Enum `Thyme Suggestion Source`: Calendar, GitHub, DevOps, Other
| sourceRef | Source Ref | Text[250], e.g. meeting or pull request ID
| sourceUrl | Source Url | Text[2048]
| evidence | Evidence | Text[2048], short reasoning
| confidence | Confidence | Enum `Thyme Suggestion Confidence`: High, Medium, Low
| status | Status | Enum `Thyme Suggestion Status`: Pending (default), Accepted, Dismissed
| timeSheetNo | Time Sheet No. | Set when accepted
| timeSheetLineNo | Time Sheet Line No. | Set when accepted
| createdBy | Created By | Text[100]
| createdAt | Created At | Defaults to the current date/time on insert
| actionedAt | Actioned At | Stamped when status leaves Pending, if blank
| lastModifiedDateTime | SystemModifiedAt | For sync
|===

Keys on (Resource No., Date) for the week view and (Resource No., Source, Source Ref, Date)
for upserts. Inserting a suggestion that matches an existing one on those four fields is
rejected so the agent can re-run without duplicates; it should `PATCH` the existing row.
Suggestions with a blank Source Ref are not checked.

=== Users (Standard BC API)

For user information, use BC's built-in https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/administration/api/dynamics_user_get[Automation API]:

----
GET /api/microsoft/automation/v2.0/companies({companyId})/users
----

Returns `userSecurityId`, `userName`, `displayName`, `state`, `expiryDate`, `contactEmail`.

**Usage:** Match the user's `userName` to a Resource's `timeSheetOwnerUserId` field.

== Security

* APIs inherit BC's standard security model
* Users need appropriate permissions on Job, Job Task, Time Sheet, Resource, and Job Ledger Entry tables
* The extension's own tables (reviews, review lines, suggestions) are not covered by the standard D365 permission sets. Assign `THYME AI AGENT` to the AI agent's Microsoft Entra application (full access) and `THYME USER` to Thyme users (read reviews; read and update suggestions)
* OAuth 2.0 authentication via Azure AD
* Supports both delegated and application permissions
